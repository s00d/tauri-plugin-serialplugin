Changelog

All notable changes to tauri-plugin-serialplugin and tauri-plugin-serialplugin-api.

4.2.2 (2026-11-14)

No API changes: Rust, JS, invoke payloads and permissions are as in 4.2.1 (and 4.0.0). serialplugin-core 0.2.2, android-usb-serial 0.1.5, serial-codec 0.1.1.

Fixes

  • read() / readBinary() with size: bytes of the same chunk past size stay for the next read (or the watch, or the idle buffer); they were dropped. A chunk arriving while a read starts can no longer land behind it in the idle buffer.
  • close() racing a disconnect no longer fails with "not open": the disconnect is recorded before the port leaves the managed set (desktop and Android), and for each CMUX channel (path#dlci=N) before the channel leaves its map.
  • tcp:// on Windows: a read into an empty buffer (read({ size: 0 })) returns at once; it waited for data or the read timeout.
  • Default (drain) exchanges: a late reply arriving while the drain starts can no longer slip into the idle buffer and complete the next command with a stale result.
  • sendAtPhases() / sendSmsPdu() with stopOnError: false: a phase whose exchange timed out reports timedOut: true (was always false). A modem error reply that mentions a timeout (+CME ERROR: network timeout) stays timedOut: false.
  • AT parser, ATV0 (numeric) replies: CR-only line ends are handled when completing, splitting and demuxing, so a URC glued behind a result code is routed and a +CUSD split by CR is joined; a numeric result code (0, 4, …) also ends a +CUSD quote left open, so later lines are not held back.
  • Android USB (android-usb-serial):
    • CH34x: a baud rate the chip cannot produce within 3.1 % is rejected (unsupported baud rate) instead of programming a wrong or zero divisor.
    • PL2303 HXN: a rate of 2^31 baud or more is rejected.
    • FTDI: the flow-control mode (and the inline XON/XOFF RX filter) changes only after the chip accepted it.
    • serialport adapter: a rejected line setting or flow mode is no longer kept as the port's config, and reading the config (baud_rate(), flow_control(), …) no longer waits for another thread's control transfer.
    • try_read: chunks that arrived before a reader error are returned before the error.
    • CDC-ACM: an IAD whose first interface is 255 no longer overflows.

Behaviour notes

  • A 4.x caller doing read({ size: 4 }) on an 8-byte burst used to lose 4 bytes; it now gets them on its next read.
  • serial_codec::at::split_lines ends a +CUSD: line at a lone CR outside its quote and splits a glued OK+URC after a CR (+CUSD: 0,"x",15\rOK is now two lines).
  • FakeTransport::script_control_in_response (feature fake-transport) answers in FIFO order, as documented (it was LIFO).

Internal

  • Tests rewritten as proptest models and Given/When/Then stories, one integration binary per crate; mutation testing (cargo-mutants, PIT for the Kotlin bridge through android/pitest.init.gradle) documented in CONTRIBUTING.md, local only.

4.2.1 (2026-11-08)

No breaking API changes; serialplugin-core 0.2.1.

Fixes

  • A local serial port whose reads return end of stream (Ok(0), e.g. a tty after hang-up / unplug) no longer busy-polls forever: three such reads in a row end in one Disconnect with reason Serial port disconnected: EOF (released as any disconnect: PortState::Disconnected, kind Disconnected); data in between restarts the count, and the hub waits a poll interval between them. Not on Android, where the USB adapter returns Ok(0) for a read timeout. tcp:// already reports its first Ok(0) (peer closed) as Disconnect.
  • BLE: an empty notification is read as "no data yet", not as end of stream.

Features (serialplugin-core 0.2.1)

  • SerialManager::open_watch_core (the open_core arguments plus options, parser, sink; returns the session path and the SubscriptionId) and insert_port_watch_core: the watch_core stream is attached before the hub's first read, so bytes sent right after open (RDY, URCs) and a Disconnect of a port that dies at once reach it; the call still succeeds in that case.

Docs

  • open_core: re-opening an open path replaces that session (watches, CMUX, hub), as open does in 4.x.

4.2.0 (2026-11-08)

No breaking API changes: Rust and JS code written for 4.x keeps compiling and the invoke payloads are unchanged. New things are new serialplugin-core (0.2.0) API.

Behaviour notes (visible to 4.x code)

  • close() now delivers what the hub still holds (the pending watch batch, a parser's remainder) to the watch before it returns, in order, with no disconnect; 4.x dropped the unflushed batch.
  • Port-list events: within one poll all removed come before all added (4.x: added first), each sorted by path. A different device on the same path between two polls (type, vid, pid or serial number changed) is removed + added; late-filled manufacturer / product strings are not.
  • CMUX: SABM is resent per the T1 / N2 given in the AT+CMUX command (the default enableMux command gives T1 = 10, N2 = 2); with neither, one SABM as in 4.x. During modem flow control (FCoff, MSC FC) channel writes wait, and fail after their write timeout.
  • ble://<name> (desktop / iOS) waits 1.5 s after the first match before taking a name, and fails if two devices share it.
  • After a disconnect the core releases the device handles (no hub restart on a dead fd), but the path keeps its 4.x behaviour until close(): managedPorts() lists it, a new watch gets the disconnect, other calls fail with the disconnect reason, close() succeeds once.
  • Rust: port::list_monitor::diff_ports reports a path that now holds another device in both lists and returns them sorted.

Features (serialplugin-core 0.2.0)

  • CoreError with ErrorKind (NotFound, PermissionDenied, Busy, Disconnected, Timeout, Cancelled, Other; platform error as source(), converts to the 4.x Error with the same text) from new methods open_core, close_core, write_core, exchange_core, at_core. A port that is listed but cannot be opened (flock, Windows "Access is denied" in any language) is Busy. The 4.x methods and errors are unchanged.
  • watch_core / unwatch_core: any number of CoreEvent streams per port, each with its own parser and routeUrc; URCs caught during at() go to every routeUrc stream. subscribe_core / unsubscribe_core: port opened / disconnected (kind Disconnected and the reason) / closed, CMUX channels included. Each core receiver runs on its own delivery thread behind a bounded queue (set_core_queue_capacity, default 4 MiB): a slow one never stalls RX, at() or close(); on overflow it gets CoreEvent::Overflow and is unsubscribed; a sink returning false is removed. Disconnect reaches each stream once (also on Android).
  • insert_port (manage any SerialPort, e.g. a fake), supports_modem_lines(path) (false for tcp://, ble:// and CMUX channels), available_ports_detailed() (typed PortDetails: u16 vid/pid, Linux /dev/serial links; USB interface number and location with the new feature usb-port-details, off by default). Features log (logs through the log crate) and test-util.
  • The old watch keeps the 4.x timing: its sink runs on the RX side, nothing is lost and nothing arrives after unwatch() / close() returns. The watch registry belongs to each SerialManager (two managers may watch the same path; a watch id stays unique across managers); "one watch per port" applies to the old watch only, with the 4.x error text.
  • Unix local serial ports: writes and control calls use a cloned handle (no wait for the RX hub's read); open(timeout) / set_timeout apply to writes, and a write longer on the wire gets twice its wire time.
  • CMUX (27.010 basic option): MSC (RTC/RTR/DV) after each data DLC is established; known control commands echoed, unknown ones answered with NSC; DISC or DM from the modem on an open DLC closes that channel (Disconnect on its path, writes fail, re-open with openMuxChannel); DISC / DM on DLCI 0 or CLD from the modem ends the session and the port is plain again; FCoff and MSC FC hold writes as above; disableMux / closing the physical port waits up to T2 for the CLD response without holding the manager's lock; CMUX writes get a timeout from the wire time. Core: CmuxSession::for_command, CmuxTimers, CmuxPhysicalIo::write_timeout.
  • TCP: keepalive (10 s idle, 5 s interval, 3 probes; Windows keeps its 10) on tcp:// sockets, best effort, so a bridge that vanished without a FIN ends in Disconnect; on Unix a keepalive ETIMEDOUT read is a disconnect. Optional allowlist for webview open(): plugins."serialplugin-config".tcpAllowlist in tauri.conf.json (exact host:port strings); without the key nothing changes, Rust callers are not restricted.
  • BLE (desktop / iOS): each write is bounded by 5 s (a timed-out write drops the link); a name shared by several devices is an error listing their ids.
  • The port-list monitor sends events outside its lock and none after unwatch_ports / unsubscribe returns.

Fixes

  • The first ExchangeWaiter result wins (a late cancel no longer replaces a completed reply); clear_buffer(Input) also drops bytes buffered in the hub; bytes_to_read no longer reports 0 while the hub holds the port; write / write_binary on path#dlci=N go out as CMUX UIH frames.
  • CMUX: enableMux waits 100 ms after the AT+CMUX OK before the first SABM (a frame inside the modem's switch window was lost and the Quectel M26 then ignored SABM for ~2 s, so open → enableMux failed with "no UA") and sends CLD if the control channel does not open; closing a channel waits up to T1 for the UA to its DISC, so disableMux gets the CLD response at once instead of waiting out T2.
  • Windows: the full USB serial number is found among every device instance with that COM name.
  • android-usb-serial 0.1.4: no panic when a driver is used before open or a control-IN reply is short (CP21xx modem status, CH34x status / break, PL2303 status, FTDI modem status).

4.1.0 (2026-11-08)

No breaking API changes: Rust and JS code written for 4.0.0 keeps compiling and the invoke payloads are unchanged; the API additions and the behaviour changes are below.

Behaviour changes (AT parser)

  • URCs are no longer de-duplicated: two identical URCs in one read are both reported.
  • V.250 numeric result codes (ATV0 mode: 0, 3, 4, …) are recognised as final results; result codes match case-insensitively.
  • Verbose +CME ERROR: / +CMS ERROR: texts are mapped to their numeric codes ("+CME ERROR: SIM busy" gives code: 14); code is null only for text the parser does not know.
  • Trailing lines after the final result code no longer hide it and are reported as URCs; a final OK glued to a following +CUSD: is split; quoted multi-line +CUSD is one URC.
  • Two-line +CMT / +CDS / +CBM URCs keep their PDU line; +CMGS: in the PDU phase of send_sms_pdu is treated as solicited; text-mode SMS bodies stay data.
  • ATV0 replies whose result code ends with CR only (V.250 §5.7.1) complete instead of timing out; echo and result are no longer glued into one line.
  • Basic commands in front of an extended one (ATE1+CSQ, AT&F+CSQ) no longer turn the reply line into a URC; with ATE0 the lines of a known command (AT+CLAC) are body.
  • CONNECT or OK followed by data in the same read (PPP, CMUX) completes the exchange.
  • A reply without a final result keeps its last line in solicitedBody.
  • The non-standard COMMAND NOT SUPPORT line is no longer a final result (only V.250, 27.007 and 27.005 codes are; SEND OK / SEND FAIL stay for compatibility).

Features

  • New serialplugin-core crate (crates/serialplugin-core): the plugin's whole serial core (RX hub, watch with parsers, exchange / AT / SMS PDU, CMUX, TCP, BLE, Android USB) without Tauri. SerialManager takes closure sinks (EventSink, PortListSink) instead of IPC channels, so headless Rust apps can drive many ports directly. The plugin is now a thin layer over it: api::SerialPort<R> keeps its 4.0.0 methods (delegating to SerialManager, which it also derefs to) and the moved modules are re-exported at their old paths (state, events, error, at, hub, …).
  • New serial-codec crate (crates/serial-codec, MPL-2.0), usable without Tauri: framing (Node serialport parser parity: delimiter, readline, byteLength, interByteTimeout, packetLength, ready, regex, startEnd, SLIP, ccTalk), at (AT response parsing), args (V.250 / 27.007 argument splitting), urc (typed 27.007 / 27.005 information lines and URCs, e.g. +CSQ, +CREG), sms (SMS PDU decode/encode, GSM 7-bit with national shift tables, UCS-2, concatenated SMS reassembly), ussd (+CUSD parsing, USSD 7-bit packing, CBS DCS) and cmux (27.010 basic-mode frames).
  • watch({ parser }) (Rust SerialPort::watch_framed / SerialManager::watch_framed; the parser is a top-level parser argument of the watch command): native framing, each complete frame is one data event with no batching; time-based parsers fire without further bytes; the buffered remainder is emitted on unwatch, close or disconnect. Works on every transport and on CMUX channels, and survives auto-reconnect. See the parsers guide.
  • JS: new exported types BlePortInfo (scanBlePorts() results with rssi) and ExchangeCompletionMode.
  • Documentation site: https://s00d.github.io/tauri-plugin-serialplugin/ (guides, platform notes, and an API reference generated from the sources).
  • Android BLE: ble://<MAC or name> ports and scanBlePorts() now work on Android (feature ble) through a Kotlin BluetoothGatt bridge: Nordic UART Service, MTU 247, serialized chunked writes, notifications as read data, link loss as onDisconnect, one retry on GATT 133/62/129. Runtime permission is requested on first use (Nearby devices on Android 12+, location on 11 and older). GATT callbacks complete only the step that waits for them (a peripheral-initiated MTU exchange or a late callback no longer finishes the wrong step); a MAC not seen before is found by a short address scan (random static addresses); names are cached and Android's 5-scans-per-30 s limit is a clear error; Bluetooth switched off ends open ports with onDisconnect; Location services off (Android 11 and older) is a clear error; pairing-protected devices are paired and retried once; one 20 s budget covers the whole open(); partial writes return the bytes sent; the RX queue is capped at 1 MiB and counted by bytesToRead(). The Bluetooth permissions are not in the library manifest (its merge would have changed apps' own location / BLUETOOTH_SCAN declarations): with ble, build.rs writes them into the app's generated AndroidManifest.xml, leaving out any the app declares itself. Apps without ble get no new permissions (see BLE).

Bug Fixes

  • watch/URC: URCs found while draining RX before an exchange were judged per read chunk, so a +CMT: / +CDS: header could go out without its PDU line; they are now emitted when the drain completes, over the whole drained buffer. A URC that arrives during the pre-exchange drain is therefore delayed by up to the drain window (drainIdleMs after the last byte, at most drainMaxMs, default 200 ms), and still reaches the watch when the drain ends with an error (read error, close, USB error).
  • watch: unwatch / close racing the RX thread could drop frames the parser had already decoded and deliver the later remainder; events now keep their sink from the moment they are decoded, and the remainder always comes after them (also on CMUX channels, where it could arrive first).
  • core: the watch sink is never called under a manager, hub, drain or CMUX lock, so a sink may call back into SerialManager (unwatch, the parser remainder on unwatch/close/re-watch and drain URCs used to run under them and could deadlock). The sink runs on the RX thread, except the last events of a watch (remainder on unwatch / close), which may run on the caller's thread; one call at a time, in order.
  • CMUX: the receive limit is the N1 from the AT+CMUX= command (4th parameter), at least 1509 bytes; frames up to N1 bytes are no longer dropped as corrupt when N1 is above 1509 (the default command keeps N1 = 31).
  • CMUX: a physical disconnect now flushes channel watches too: their parser remainder, then disconnect with the channel's path.
  • watch: time-based parsers (interByteTimeout, ccTalk) and the batch timer kept running only outside a pre-exchange drain; they now fire during it.
  • core: watch ids handed out by SerialManager::watch / watch_ports skip ids already taken by plugin channels, and a duplicate id is rejected instead of silently replacing the other watch. force_close joins the RX thread outside the port map lock.
  • watch: unknown keys inside watch({ parser }) fail watch (a typo would fall back to a default); the parsers are linear on input without delimiters (startEnd and regex rescanned their whole buffer per read), and packetLength gained maxBufferSize and rejects options that could overflow. Exchanges judge each reply line once (a long reply re-ran completion over the whole buffer per read).
  • BLE: chunks are capped at 512 bytes (Android 14+ and some desktops negotiate MTU 517+); ble://<name> lookups scan without the service filter (boards that do not advertise the NUS UUID); every 8th chunk is written with response when the device allows it. Desktop / iOS: open() times out after 20 s instead of waiting forever on macOS, one Bluetooth adapter is shared and waited for until powered on, notifications sent right after subscribing are kept, Linux ports are ble://<MAC> and MACs match in any case, the RX queue is capped at 1 MiB like on Android. Android: bonded devices get 1.6 s before service discovery, a stale GATT cache is refreshed once, Service Changed ends the port, high connection priority, indicate-only TX characteristics work.

4.0.0 (2026-11-08)

Full audit release. See the migration guide for the breaking changes.

⚠ Breaking changes

  • Rust commands::* port I/O functions are async (they ran on the main thread and a read waiting for data froze the UI). Add .await. MSRV 1.79 → 1.90.
  • npm exports split into import/require with separate types (index.d.cts); guest-js/ sources and the development condition are no longer published.
  • read() decodes bytes in JS (port encoding, streaming); watch() no longer uses the read timeout as its batch window (default ~20 ms, plus flush at size).
  • Android device_filter.xml no longer matches every USB device.

Features

  • Serial over TCP: tcp://host:port on every platform (ser2net, ESP-Link, device servers).
  • The plugin builds for iOS (it did not compile there at all); TCP is the transport.
  • dtr / rts options on open (new SerialPort({ dtr: false, … }), Rust commands::open(…, dtr, rts) / SerialPort::open_with_lines): dtr: false stops Arduino-style boards resetting on every open. Android still asserts both by default.
  • Serial over Bluetooth LE (Nordic UART Service): ble://<id> paths and SerialPort.scanBlePorts(), behind the ble cargo feature (desktop + iOS).

Bug Fixes

  • exchange/AT: cancel_exchange wedged the port's transaction queue for good (the next exchange waited forever).
  • exchange/AT: a late reply left in the buffer completed the next default exchange, shifting all later responses by one.
  • exchange/AT: SMS prompt "\r\n> " (no LF) was never detected, so send_sms_pdu always timed out; +CMS ERROR/ERROR after AT+CMGS waited for the timeout; a non-UTF-8 byte or a URC right after OK stalled completion; "AT\r" lost its CR.
  • exchange/AT: a cancel between at_phases / send_sms_pdu phases was wiped and the SMS was sent anyway; URCs after the echo were swallowed; the URC demux of the previous exchange was reused.
  • CMUX: frames used HDLC-style 0x7E stuffing with a CRC-16 instead of 27.010 basic mode, so no modem understood them; no SABM/UA or CLD; stream flush deadlocked the RX thread; DLCI was not range-checked; enable_mux ignored ERROR; virtual channels survived their physical port.
  • watch: with routeUrc data lost its line terminators and lines split across reads were not joined; on Windows an unplugged adapter never produced disconnect; EINTR silently stopped the RX thread.
  • ports: unwatch_ports could deadlock the app; re-opening a port (webview reload) left the old watch registered; a failed open could leave an Opening entry or a running hub thread; ports are closed on app exit; large or slow writes failed after a fixed 100 ms timeout.
  • guest-js: handle.unwatch() did not free the port for a new watch(); close() after a disconnect did not stop auto-reconnect; set* changes were lost on reconnect; open() failing in configureAtSession left the port open; auto-reconnect gave up when the re-watch failed; concurrent watch() started two native watches; sendAtPhases sent binary phases as objects; onReconnect always reported attempt 0.
  • android: PL2303 and FTDI chip detection read the wrong descriptor; FTDI baud 0 panicked; device_filter.xml had unparsable ids (wildcards) and wrong STM32/Arduino ids; a 30 s USB permission wait held the device lock the detach handler needed; the fd leaked when an open failed part way; detach teardown ran on the UI thread.
  • android: USB Ethernet / RNDIS devices (a CDC data interface without an ACM control interface) were listed as serial ports; an out-of-range CDC port index silently opened another port; a CDC notification error was reported only once; clear(Input) left chunks the reader had already queued; a write that timed out half-way (flow control) reported nothing sent, so write_all resent it; a USB chunk bigger than the read buffer lost its tail. FTDI latency timer is set to 1 ms (chip default 16 ms per short reply). CH34x gains RTS/CTS flow control and the 307200 baud divisor; PL2303 no longer sends rates older chips reject; FT4232H counts 4 ports. (Compared against usb-serial-for-android 3.11 / master.)
  • windows: full USB serial numbers come from the registry instead of wmic, which is gone from Windows 11 24H2+ and flashed a console window on every port-list poll.
  • docs: six permission identifiers in the README did not exist.

Build

  • guest-js: Vite 8 library build (ESM + CJS), TypeScript 6, vitest 5; publint, arethetypeswrong and a CJS/ESM smoke check run on every build. Rollup, Jest and tslib removed.
  • Android library: compileSdk 36, AGP 8.11, Kotlin 2.2 compilerOptions; unused appcompat/material/gson dependencies removed.
  • CI on Linux, macOS and Windows (Windows test binaries embed a Common-Controls v6 manifest), MSRV job, Android and iOS checks.
  • android-usb-serial 0.1.3.

3.0.0 (2026-07-08)

Major v3 release: Channel-based watch() API, native AT exchange / FIFO queue, unified RX hub on desktop and Android, and a hard cut from vendored Java usb-serial-for-android to the pure-Rust android-usb-serial crate (nusb).

Breaking Changes

  • Streaming API: startListening() / listen() / disconnected() / cancelListen() removed. Use watch({ onData, onDisconnect?, onError?, onUrc? }) → SerialEvent over Tauri Channel (desktop + Android).
  • Capabilities: SerialPort.getCapabilities() (transport, platform, version); commands capabilities, watch, unwatch replace start_listening / stop_listening.
  • Removed: available_ports_direct — use available_ports().
  • Removed AtCommandQueue / port.at: Use sendAt(), sendAtPhases(), sendSmsPdu(), cancelAt(), configureAtSession().
  • onUrc removed from AtSessionOptions: Use watch({ onUrc }) for live URC lines.
  • exchange() returns ExchangeResponse, not Uint8Array. Use .raw for bytes.
  • clearRx: true maps to purge; default is now drain when unset.
  • Android USB stack: Vendored android/usbserial Java tree removed. Kotlin no longer runs serial I/O commands on the main thread — only UsbFdBridge (enumerate, permission, fd). All drivers and bulk I/O live in Rust (android-usb-serial + nusb).
  • Rust module layout: Removed compat top-level modules (desktop_api, mobile_api, port_rx_hub, exchange_runtime, …). Use api::serial, hub, exchange, port, state, android.
  • guest-js: AtCommandResult.raw / ExchangeResponse.raw are Uint8Array; timedOut is a native boolean.
  • rust-version: 1.79 minimum.

Migration (v2 → v3)

v2v3
startListening() + listen(fn)watch({ onData: fn })
disconnected(fn)pass onDisconnect: fn into the same watch({ ... })
cancelListen() / stopListening()handle.unwatch()
port.at.enable() / enqueue()sendAt() / sendAtPhases()
Kotlin UsbBridge + Java driversUsbFdBridge fd → Rust driver_host

Android app requirements: uses-feature android.hardware.usb.host, device_filter.xml, runtime USB permission before openDevice(). Do not claimInterface() in Kotlin before handing fd to Rust. See crates/android-usb-serial/README.md.

Features

  • android-usb-serial crate: Pure Rust USB serial on Android via nusb; 567 golden parity fixtures; drivers for FTDI, CP21xx, CH34x, PL2303, CDC-ACM, GSM modem, Chrome CCD (20b54c0).
  • UsbFdBridge: Kotlin provides USB fd only; Rust driver_host owns probe, claim, drivers, RX reader, and I/O.
  • Unified api::serial: Single serialport::SerialPort facade on desktop and Android; PortRxHub poll-loop on both platforms (4071ff6).
  • Rust-first Android JNI (29faa29): bulk-IN reader thread, chunked write, CMUX virtual paths through Rust session.
  • Unified RX hub (desktop + Android): Single consumer per port; watch, exchange, read, and drain share one hub (7024fc0, caa5700).
  • take_idle_bytes: Stale RX in the hub idle buffer is replayed into the next exchange after write.
  • Native FIFO queue (Rust + Android): All exchange / AT jobs on one port serialize in FIFO order; parallel invokes wait instead of "Exchange already in progress" (e1eb63f).
  • Native exchange / cancel_exchange: Write + read-until terminators, idle silence, wall timeout, max response size; structured ExchangeResponse (status, lines, solicitedBody, urcLines, raw).
  • Line-framed AT completion: Final line OK / ERROR / +CME ERROR / +CMS ERROR; completionMode: 'substring' for legacy/binary.
  • rxPrepare: Default drain; purge opt-in; none unchanged.
  • watchAvailablePorts() / watch_ports: Hotplug via Channel — snapshot, then added / removed (desktop poll; Android USB attach/detach).
  • open() canonical path: Returns session key (Android device path / device#N for multi-port).
  • CMUX virtual exchange: Paths physical#dlci=N routed through Rust CMUX session like desktop.
  • usb-driver-tester: Standalone hardware self-test app under examples/usb-driver-tester/.
  • guest-js: Modular v3 SDK; auto-reconnect restores open() + watch() after disconnect.
  • macOS: available_ports({ singlePortPerDevice: true }) — one path per device (prefers /dev/cu.*).
  • Extended AT grammar: Vendor prefixes, V.250 finals, derive_solicited_prefixes(command); ExchangeDemux for live URC before echo.
  • pauseWatch default false — watch stays on during AT; pass pauseWatch: true for legacy behavior.

Bug Fixes

  • Android CH340 / weak OTG: Bulk IN reader starts after line/DTR setup; in-flight URBs reduced to 2; clearer detach reason in logs.
  • Android enumerate: Kotlin exports interfaces[]; Rust expands multi-port paths (device#N) via ProbeTable without opening fd.
  • Android write after listen: EndpointPair::write no longer re-opens bulk IN owned by SerialReader (endpoint already in use).
  • Android Kotlin fd bridge: Removed pre-claimInterface (fixes io interface is busy with nusb detach_and_claim).
  • Android logcat: Rust plugin logs use tag SerialPlugin via __android_log_write.
  • Android: USB permission PendingIntent uses FLAG_MUTABLE on API 31+; detach + IO errors → SerialEvent::Disconnect on Channel (#27).
  • Android: cancel_exchange wakes hub waiter; CMUX virtual cancel clears DLCI TX queue (c6c94dd).
  • Android: JNI exceptions, session path re-key, teardown leaks (e9fc307).
  • Android: Serialize fail/shutdown on dedicated usb-io thread (cd74b84).
  • desktop: write / write_binary flush via write_all (#29).
  • desktop: Unblock hub drain when watch is active (55f1cb3).
  • desktop: Lock order, Opening-state open, async enable_mux (3a4bd88).
  • desktop (Windows): Enrich truncated USB serial_number from WMI (#23).
  • Hub / watch: lock_or_recover in watch_registry and hub channel paths (2071e15); panic/poison hardening (8672de9).
  • TX queue: Errors no longer halt the port queue until reopen (e1eb63f).
  • guest-js: readBinary requires open port; watch-preserving change() (9b22af7).

Build / CI / Docs

  • CI: cargo fmt, clippy, pnpm check / build, Windows cargo check, Android integration emulator job (1aa1682, 2e70ecf).

2.23.0 (2026-07-02)

2.22.0 (2026-03-21)

Android / USB

  • Lifecycle: SerialPlugin registers Application.ActivityLifecycleCallbacks and runs SerialPortManager.cleanup() when the host Activity is destroyed (close USB ports, unregister permission receiver, shut down IO executor).
  • Listening: Incoming data is coalesced in BufferedEmitter / SerialByteAccumulator before serialData events; flush interval via serialDataFlushIntervalMs (native clamp typically 10–2000 ms).
  • USB serial (usb-serial-for-android): Read/write use configured timeouts; clearBuffer maps to purgeHwBuffers when supported; setFlowControl (RTS/CTS, XON/XOFF); SerialInputOutputManager errors trigger serialError and port cleanup.
  • bytesToRead / bytesToWrite (Android): With active watch, bytesToRead is the plugin-side buffer before the next Channel flush; bytesToWrite is typically 0.
  • Tooling: Gradle wrapper and android/ settings for local ./gradlew test; JVM unit tests use a real org.json artifact (Android JSON stubs break JSONObject.put in tests). Kotlin tests cover models, JSON helpers, emit pipeline, BufferedEmitter.

Features

  • guest-js: Stricter SerialportOptions / Options typing (removed open index signatures); Record<string, PortInfo> for available_ports maps.
